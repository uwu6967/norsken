# Rules

The rules every change must follow. They come from `CONTRIBUTING.md` and from what Danny has asked
for. If a rule here and the code disagree, the rule wins and the code is a bug.

## Privacy (taushetsplikt)
- **Never** commit guest names, phone numbers, e-mail addresses or photos – not in code, tests, notes,
  commit messages or screenshots.
- Real booking lists or photos shown while explaining a problem are only for understanding; rebuild
  the case with made-up names (Testa, Testb …) for tests and notes.
- Guest data lives only in the browser (`norsken-guests-v1` in localStorage). It is never part of the
  shared plan (`state`), never sent anywhere. See [[Storage and data]] and [[ResDiary import]].
- The ResDiary buttons read only time, party size, surname, comment, area and ResDiary's table –
  never phone or e-mail.

## Git and releases
- Finished work goes **straight to `main`**. The other branches on GitHub are kept as they are.
- Every push to `main` makes a release (`Norsken.zip` + `LES-MEG.txt`). **The commit messages are the
  release notes**: plain English that Danny can read – a title and a short list of what changed for
  the user.
- Author **and** committer on every commit: `uwu6967 <22033341+uwu6967@users.noreply.github.com>`.
  No co-author lines.
- Nothing on GitHub mentions how the code was written: no tool names and no
  "generated by" lines – in files, commit messages or notes.
- The rights belong to **Daniel Hj** – all rights reserved, not open source (`LICENSE`).

## Building
- Change only `src/` and `resdiary/` by hand. Then run `python3 tools/build.py` and commit everything
  it writes: `index.html`, `print.html`, `bokmerke.html`, `extension/`, `LES-MEG.txt`,
  `resdiary/README.md`. Nobody who uses the app should ever have to build. See [[Files and build]].
- After a push, update the hosted copy as well (it is the same `index.html` with `print.html`,
  `src/app.js` and `src/styles.css` beside it). Keep the `window.claude` lines – the hosted copy needs
  them for its shared plan and for printing.

## Design
- Norwegian UI, few words, big buttons. Made for the boss and older colleagues.
- One press for the boss's daily flow (import → shift → print). See [[Shifts and start screen]].
- Every action that removes or replaces something offers «↶ Angre».
- Works on a phone. The top bar fits one row from 1280 px wide; below that the shift buttons wrap.
- The first render must not touch anything declared further down the file (see [[Render loop]]).
